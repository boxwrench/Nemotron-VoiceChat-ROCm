## Renderer/TTS-disabled VC01 service curve

The first one-frame run still loaded native TTS and enabled the D1 worker in
discard-sink mode. It was therefore unsuitable for renderer-disabled service
attribution. Runtime `11b808ec73aa331f06e6ce357eaa18dcbb00b959` adds explicit
research controls; the replacement run used `live_start` with both
`renderer:false` and `tts:false`.

The 37 consecutive VC01 slices each authorized exactly one D3 frame. The raw
per-frame durable evidence is
`generated/D3-service-curve/renderer-off-vc01.csv`.

| Metric | First frame | Frames 2–37 |
| --- | ---: | ---: |
| perception | 77.389 ms | p50 24.909 ms; p95 32.423 ms; p99/max 33.329 ms |
| main | 52.251 ms | p50 52.264 ms; p95 62.932 ms; p99/max 68.616 ms |
| total | 129.640 ms | p50 78.206 ms; p95 88.590 ms; p99/max 93.704 ms |
| >80 ms misses | 1 / 1 | 8 / 36 (22.2%) |

The first-frame perception result is therefore cold/transient, not
representative of steady D2 execution. Over this partial history fill, logical
state rose from 988,064 to 8,078,240 bytes; perception did not show a matching
upward service-time trend. VC01 ends before the known 14,548,992-byte encoder
state plateau, so it does not itself prove the plateau service curve.

The runtime reports no literal queue because this controlled harness sends the
next request only after the prior reply. Against a real 80 ms capture cadence,
the deterministic cumulative service-minus-cadence debt peaks at 62.964 ms and
ends at 15.426 ms. The combined service path—not a standalone perception
failure—is therefore the current blocker.

Classification: **D3_COMBINED_SERVICE_BLOCK**. Do not optimize from this run;
the next work must first attribute the combined main/perception tails and then
measure the real renderer/ALSA interaction.
